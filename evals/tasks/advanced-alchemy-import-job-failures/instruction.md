# Track import job failures

Import jobs in `/app/app/imports/` fail now and then. The worker calls `ImportJobService.mark_failed(job_id)`, so the reason is lost. Support needs to see why a job failed and when, and the retry worker needs to know how many times a job has failed.

Please add:

- `ImportJobService.record_failure(job_id, message)`. The worker will call it instead of `mark_failed`. The job should still end up with status `failed`.
- `ImportJob.attempts`: the number of failed attempts for a job. It has to work on a loaded job (`job.attempts`) and in queries, e.g. the retry worker runs `select(ImportJob).where(ImportJob.attempts < 3)`.

Alembic migrations are autogenerated from the models, so you don't need to write one. The database is PostgreSQL; our tests run against SQLite.
